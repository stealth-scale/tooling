# Motion

Motion says what kind of thing is happening: something arriving, something leaving, something
answering a press. That meaning should not change between products, so the curves and the
durations are the same in every theme.

## Easing

Four curves. Run them together: a curve is invisible in a table of `cubic-bezier` values, and
the only way to tell `ease-out` from `ease-spring` is to watch them start and stop side by
side.

<Easings />

- `ease-out` is for anything arriving. It starts fast and settles, which reads as the thing
  already being on its way.
- `ease-in` is for anything leaving. Slow to commit, then gone.
- `ease-in-out` is for something moving between two places on screen, where both ends matter.
- `ease-spring` is for a direct answer to a press or a drag, where a small overshoot reads as
  physical rather than as a glitch.

## Duration

<Durations />

`fast` is for a state change on something already under the pointer, such as a hover or a
press. `normal` is the default for anything appearing or disappearing. `slow` is for something
large enough that the eye has to follow it across the screen. Anything past a third of a
second reads as waiting rather than as motion.

## Animations

Which animations exist is a contract, not a theme's choice: a component writes
`animate-fade-in` and every theme has to have one. `core-theme` names them and each is built
from the durations and easings above, so retuning a curve moves the whole vocabulary at once.

<Animations />

An entrance carries `backwards` and an exit carries `forwards`. Without them an entrance shows
one frame at full opacity before it starts and an exit snaps back to visible the instant it
ends, which reads as a blip rather than as motion. A collapse animates to
`--collapsible-panel-height`, which the component measures and sets, because a keyframe cannot
animate to `auto`.

## Responding to the pointer

An animation is something the page does; a response is something a control does when a person
touches it. The theme writes the second as two classes, so a component states that it responds
without deciding how fast or to what.

```tsx
<button className="motion-state">Save</button>
<button className="motion-press">Delete</button>
```

<Responses />

`motion-state` eases the properties a hover, a focus or a disable actually touches — colour,
fill, border, shadow, opacity and the three transform properties Tailwind writes separately —
at the fast duration on the out curve. `motion-press` adds the shrink to `--press-scale` while
the control is held, which is the one thing a pointer gets that a hover colour cannot say.

Neither names reduced motion. The rules below already hold every element on the page to a
hundredth of a millisecond, with `!important`, so a class repeating the check would be
restating a rule that has already won.

## Reduced motion

The **Motion** toolbar forces the reduced path without changing your system settings, and a
design system honours it by collapsing every animation and transition to almost nothing rather
than to zero. That distinction matters: an animation still fires `animationstart` and
`animationend`, so a component that waits for one before unmounting still completes instead of
hanging open. Check any component whose meaning depends on movement with the toolbar on.
